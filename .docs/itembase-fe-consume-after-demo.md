# ItemBase FE Consumption Guide - Post Demo Revision

## 1. Item Management > Parents

### Parent list now includes `item_count`
Use the existing list endpoint:

```http
GET /api/item/item-parents
```

Each parent object now contains:

```json
{
  "id": "...",
  "parent_code": "P002034",
  "parent_name": "ASA ASAHO LUNCH BOX",
  "item_count": 0
}
```

FE rule:
- show **Delete** only when `item_count === 0`;
- BE also validates this, so delete is rejected if the parent still has items.

### Delete parent

```http
DELETE /api/item/item-parents/:id
```

A parent can only be deleted when its current item count is `0`.

### Parent name and uniqueness
`parent_name` is now generated by BE. FE does not need to generate it.

Formula:

```text
Brand Name + Sub Brand + Item Name
```

Example:

```text
ASA + ASAHO + LUNCH BOX
=> ASA ASAHO LUNCH BOX
```

The combination **Brand + Sub Brand + Item Name** must be unique. The check is trim/case-insensitive on create and update.

## 2. Item Management > Items - Variant Value Suggestion Field

Existing values can still be submitted by ID:

```json
{
  "variants": [
    {
      "attribute_id": "ATTRIBUTE_UUID",
      "value_id": "VALUE_UUID"
    }
  ]
}
```

For a new free-text value, FE can send:

```json
{
  "variants": [
    {
      "attribute_id": "ATTRIBUTE_UUID",
      "value_name": "Dark Blue"
    }
  ]
}
```

BE behavior for a new value:

```text
input       = Dark Blue
stored name = DARK BLUE
stored code = DARK_BLUE
```

If the value already exists under the selected attribute, BE reuses the existing record instead of creating a duplicate.

## 3. Item / Bundle Export

Old endpoint:

```http
GET /api/item-data/export
```

is replaced by:

```http
GET /api/item-data/export/items
```

This endpoint exports both `regular` and `bundle` rows.

### Status behavior

```http
GET /api/item-data/export/items
```
Exports **all Active + Inactive** items.

```http
GET /api/item-data/export/items?status=active
```
Exports Active only.

```http
GET /api/item-data/export/items?status=inactive
```
Exports Inactive only.

No date filter is used for XLSX export.

### Default columns
Always included and always in this order:

1. Business Unit
2. Channel Name
3. Category
4. Parent ID
5. Parent Name
6. SKU ID
7. SKU Type
8. SKU Name

`SKU Type` value is `Regular` or `Bundle`.

### Optional columns
Send optional field keys using `fields`, comma separated. Output order stays fixed regardless of checkbox click order.

| Field key | XLSX header |
|---|---|
| `main_category` | Main Category |
| `sub_category` | Sub Category |
| `brand_category` | Brand Category |
| `pic` | PIC |
| `sku_created_date` | SKU Created Date |
| `sku_updated_date` | SKU Updated Date |
| `sku_status_date` | SKU Status Date |
| `port` | Port |
| `item_source` | Item Source |
| `selling_name` | Selling Name |
| `uom` | UOM |
| `qty_per_pack` | Qty/Pack |
| `height` | Height |
| `width` | Width |
| `depth` | Depth |
| `gross_weight_pack` | Gross Weight/Pack |
| `lead_time` | Lead Time |

Example:

```http
GET /api/item-data/export/items?status=active&fields=main_category,pic,sku_created_date,sku_updated_date,sku_status_date,port
```

Date columns are returned as:

```text
YYYY-MM-DD
Asia/Jakarta / GMT+7
```

Date sources:
- SKU Created Date = `items.created_at`
- SKU Updated Date = `items.updated_at`
- SKU Status Date = latest `activity_logs.created_at` where `entity_type = items`, `entity_id = items.id`, `action = STATUS_CHANGE`

Multiple Business Units, Channels, PICs, or Ports stay in one item row and are joined with `,`.

## 4. Parent Export

```http
GET /api/item-data/export/parents
GET /api/item-data/export/parents?status=active
GET /api/item-data/export/parents?status=inactive
```

No `status` means all parent rows.

### Default columns
1. Business Unit
2. Channel Name
3. Category
4. Parent ID
5. Brand
6. Sub Brand
7. Item Name
8. Parent Name

### Optional columns

| Field key | XLSX header |
|---|---|
| `main_category` | Main Category |
| `sub_category` | Sub Category |
| `brand_category` | Brand Category |
| `pic` | PIC |
| `parent_created_date` | Parent Created Date |
| `parent_updated_date` | Parent Updated Date |
| `parent_status_date` | Parent Status Date |
| `port` | Port |
| `item_source` | Item Source |

Date sources:
- Parent Created Date = `item_parents.created_at`
- Parent Updated Date = `item_parents.updated_at`
- Parent Status Date = latest `activity_logs.created_at` where `entity_type = item_parents`, `entity_id = item_parents.id`, `action = STATUS_CHANGE`

## 5. Inactive Item JSON Endpoint

Existing endpoint remains:

```http
GET /api/item-data/inactive-items
```

Optional query:

```text
page
limit
search
date_from=YYYY-MM-DD
date_to=YYYY-MM-DD
```

## 6. Parent / Item / Bundle Import Templates

### Download templates

```http
GET /api/item-data/templates/parents
GET /api/item-data/templates/items
GET /api/item-data/templates/bundles
```

Every main input sheet contains one clearly marked EXAMPLE row directly below the header. BE ignores this example row during preview/import.

### Parent sheet - `Parents`

Headers in exact order:

```text
Parent ID
Brand
Sub Brand
Item Name
Category Detail
Item Source
Ports Code
Variant Attribute
Status
```

Notes:
- `Parent Name` is removed; BE generates it.
- `Brand` accepts the master Brand name; BE also tolerates Brand code.
- `Ports Code` uses port code; multiple values use `;`.
- `Variant Attribute` uses attribute code; multiple values use `;`.
- `Status`: Draft / Active / Inactive / Discontinued.
- Sheet `Ref Item Types` is renamed to `Ref Item Sources`.

### Item sheet - `Items`

```text
SKU ID
SKU Name
Parent ID
UOM Code
Qty/Pack
Height
Width
Depth
Gross Weight/Pack
Lead Time
Variant Attribute Value
Status
```

Variant format example:

```text
COLOR=DARK_BLUE;SIZE=L
```

### Bundle sheet - `Bundles`

```text
SKU ID
Selling Name
Parent ID
Status
```

`UOM Code` is removed. BE automatically assigns active UOM code `SET`. If `SET` does not exist/is inactive, preview rejects the row.

### Bundle sheet - `Bundle Components`

```text
SKU ID Bundle
SKU ID Component
Qty
Sort Order
```

Existing bundle rules remain: 1-5 components, regular items only, and if there is only one component its Qty must be greater than 1.

### Import flow

```http
POST /api/item-data/imports/:type/preview
POST /api/item-data/imports/commit
DELETE /api/item-data/imports/preview/:token
GET /api/item-data/imports/errors/:token
```

`:type` = `parents`, `items`, or `bundles`.

## 7. Master Export / Import

Supported master types:

```text
brands
categories
item-sources
ports
uoms
variant-attributes
variant-values
sub-brands
```

### Export

```http
GET /api/item-data/export/masters/:type
GET /api/item-data/export/masters/:type?status=active
GET /api/item-data/export/masters/:type?status=inactive
```

No status means Active + Inactive.

Static XLSX headers:

| Type | Headers |
|---|---|
| brands | Code, Name, Status |
| categories | Category, Sub Category, Main Category, Brand Category, Status |
| item-sources | Item Source Code, Item Source Name, Status |
| ports | Country Code, Port Code, Port Name, Status |
| uoms | UOM Code, UOM Name, Status |
| variant-attributes | Attribute Code, Attribute Name, Status |
| variant-values | Attribute Code, Value Code, Value Name, Status |
| sub-brands | Sub Brand, Status |

### Master template

```http
GET /api/item-data/templates/masters/:type
```

The import header is the same as the export header and the template contains one ignored EXAMPLE row.

For Sub Brand, `normalized_name` is not exposed. BE fills it automatically from `Sub Brand` using lowercase normalization.

### Master import

```http
POST /api/item-data/imports/masters/:type/preview
POST /api/item-data/imports/masters/commit
DELETE /api/item-data/imports/masters/preview/:token
GET /api/item-data/imports/masters/errors/:token
```

Preview uses the same preview-token flow as item imports.

## 8. FE Migration Checklist

- Replace `/api/item-data/export` with `/api/item-data/export/items`.
- Parent export uses `/api/item-data/export/parents`.
- Export modal default status selection can still be Active in UI, but **do not send `status`** when the user chooses All.
- Change Item export labels to `SKU ID`, `SKU Type`, `SKU Name` and new SKU date field keys.
- Use `item_count` to control Parent Delete visibility.
- Consume `DELETE /api/item/item-parents/:id`.
- Do not send/generate Parent Name manually.
- Item variant suggestion can submit `value_name` when the typed value does not yet exist.
- Update import template headers exactly as documented above.
- Bundle import no longer sends UOM; BE uses `SET`.
- Add Master export/template/import actions using the master type slugs above.
